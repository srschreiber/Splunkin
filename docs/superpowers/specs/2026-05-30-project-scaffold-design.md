# dungeoncrawl — Project Scaffold Design

**Date:** 2026-05-30
**Status:** Approved

## Goal

Stand up a buildable C++ skeleton for a Barony-inspired 3D dungeon crawler. The
first milestone is a window that opens an OpenGL 3.3 core context and draws a
single triangle through the core game loop. Every other engine subsystem exists
as a stub so the architecture is visible without being overbuilt.

Multiplayer is planned (UDP for gameplay, TCP for login/lobby) but is **only
scaffolded, not wired to anything** in this milestone.

## Decisions

| Decision | Choice | Rationale |
|---|---|---|
| Dependency management | Vendored in tree | Self-contained, reproducible, no reliance on system package state |
| First runnable target | Hello triangle | Proves the full platform + renderer pipeline end-to-end |
| Multiplayer structure | Single binary (host or join), `net/` stubbed and inert | Player-hosted model like Barony; avoids premature client/server split |
| Language / compiler | C++17, clang++ | macOS default toolchain |
| Windowing/audio/input | SDL3 | Current SDL line |
| Font rendering | stb_truetype | Single-header vendored, no extra submodule build |
| Submodule libs | Built as static | Simpler linking |
| Build orchestration | Thin `Makefile` delegating to `scripts/` | Per user request: `make` calls `/scripts` to build |

## Dependencies (vendored)

**Single-header, committed under `third_party/`** (fetched by `setup.sh`):
- `stb_image.h` — image/texture loading
- `stb_truetype.h` — font rasterization
- `cgltf.h` — glTF model loading
- `nuklear.h` — immediate-mode UI

**Generated by `setup.sh`:**
- GLAD for `gl:core=3.3` via the `glad2` pip package → `third_party/glad/`
  (`glad.c` + `include/glad/gl.h` + `include/KHR/khrplatform.h`)

**Git submodules, built from source (static) by `setup.sh`:**
- `SDL` (SDL3) — windowing, input, audio
- `cglm` — vector/matrix math
- `ReactPhysics3D` — physics (present for later use)
- `enet` — reliable UDP + TCP transport (present for later networking; unused now)

## Build System

`make` is thin; real logic lives in `scripts/`.

| Command | Action |
|---|---|
| `make setup` | `scripts/setup.sh` — one-time: fetch headers, `git submodule update --init --recursive`, build SDL/cglm/ReactPhysics3D/enet static libs, generate GLAD |
| `make` / `make build` | `scripts/build.sh` — compile `src/**` + `glad.c`, link against built static libs → `build/dungeoncrawl` |
| `make run` | `scripts/run.sh` — build then launch the binary |
| `make clean` | `scripts/clean.sh` — wipe `build/` (keeps `third_party/`) |

`build.sh` is a direct clang++ invocation: C++17, `-Ithird_party -Ithird_party/glad/include -Isrc`,
compiles sources to `build/obj/`, links the submodule static libs plus the macOS
OpenGL framework. No CMake.

## Milestone Behavior (`make run`)

1. SDL3 initializes; a window is created with an OpenGL 3.3 core context.
2. GLAD loads GL function pointers.
3. The core loop runs: `process_input() → update(dt) → render()`.
4. A single colored triangle is drawn from `assets/shaders/tri.vert` and
   `assets/shaders/tri.frag` (VAO + VBO).
5. Clicking the window close button or pressing a quit key exits cleanly,
   releasing GL and SDL resources.

## Stubs

Every engine subsystem other than `platform/` and `renderer/` is a header with
its namespace/struct sketched and a `// TODO` comment. It compiles and links but
does nothing yet:

- `input/`, `audio/`, `assets/`, `world/`, `entity/`, `ui/`, `game/`
- `net/udp_channel.h` (gameplay channel interface sketch) and
  `net/tcp_channel.h` (login channel interface sketch) — interfaces only,
  nothing constructs or calls them.

## Out of Scope (future specs)

- Real networking protocol / replication
- ECS, job system, scripting, custom allocators
- Asset pipeline, level format
- Lighting, frustum culling, texture atlases beyond the triangle
- UI wired through Nuklear
